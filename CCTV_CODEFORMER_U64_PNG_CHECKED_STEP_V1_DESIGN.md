# Select a finite step using actual TRAIN PNG outcomes

23 October 2026. **Prospective design only: no runnable worker, sealed transfer
or launch guide exists.** A separate pure-array selector prototype may support
source tests; it does not implement or execute the VM test.
The [audited zero-update measurement](CCTV_CODEFORMER_U64_PNG_SURROGATE_MEASUREMENT_V1_RETURN_REVIEW.md)
shows that adding the measured PNG identity-surrogate vectors would yield almost
the same direction as the rejected RAW-only pilot. Another near-identical
gradient-direction pilot is not the selected corrective approach.

## Question and changed mechanism

Can a predeclared finite step that actually preserves the delivered PNG on the
optimization TRAIN cohort also pass the unchanged, separate monitor/guard bank?
This tests measured finite output behavior rather than treating a negative
gradient dot as a PNG certificate. It is not a claim that more epochs, a bigger
learning rate or a different optimizer will recover missing facial information.

The prior failure stays binding. Initialize exact original trained u64, including
its frozen R2/U96 base. Never initialize from failed update two or retrospectively
select the old update-one state. No developer or agent auto-launches the test.

## Proposed finite protocol

1. Reconstruct and independently authenticate the original-u64 eight-RAW pooled
   direction from the already audited 256-query measurement's RAW witnesses.
   All four TRAIN roles remain. Require exact 575-state initialization, stored
   RAW/PNG parity and fixed deterministic execution. Do not claim that reusing
   a saved direction creates a new optimizer or new autograd measurement.
2. Evaluate four predeclared candidate maximum coordinate bounds, in this fixed
   order: **2e-5, 1.5e-5, 1e-5, 5e-6**. Use the existing fixed 0.99 numerical
   headroom before FP32 rounding. Each candidate is formed independently from
   original u64, never from the preceding trial. The previous 2.5e-5 pilot step
   is excluded from eligible candidates. Every actual rounded displacement
   must stay within the original 2.5e-5 per-application bound and the separate
   1e-4 original-relative cumulative bound, and retain all 539 base
   and adapter tensors bitwise. Each restore and final selected application
   needs the same actual rounded bounds. Candidate and final selected forward
   displacement must retain all eight strictly negative RAW pooled gradient
   dots after rounding. A restore is explicitly labeled as a reversal, not a
   descent step; its actual destination must equal original heads bitwise.
   Retain every trial and its actual arrays.
3. For each candidate, save all 64 optimization cases and recompute the same
   16 actual RAW/PNG role-mean MAE/adjacent endpoints, with local central128 and
   other whole256 regions. Eligibility requires all 16 means to be no greater
   than original u64, and both blur PNG adjacent means strictly smaller. Quality
   comparisons keep zero tolerance. Selection requires all four complete banks
   with exactly the same 64 IDs, target bindings and ROIs. Its API accepts no
   monitor or guard records. Select the first eligible candidate in the
   predeclared order only after retaining all four trials. If none qualifies,
   retain the stop; do not append scales or introduce a new selection criterion.
4. The monitor/guard bank is excluded from candidate selection. After the fixed
   optimization-only selection, execute its 56 cases once. Preserve all original
   inherited gates, the 1% blur improvement against frozen U96, clear/low-light
   requirements and the additional 16 endpoint nonincrease checks against
   original u64. A monitor/guard failure rejects the entire test; do not try the
   next candidate, select old update one, relax a threshold or resume training.
5. Record initial/final full575 states, all trial head values, rounded deltas,
   displacement certificates, state transitions, source/target bindings, RAW/PNG
   outputs, individual regressions, RNG/sampler/null-optimizer state, resource
   records and any partial/failed outcome. Independently audit returns and all
   planned sheets. A successful one-step screen is not a useful-restoration,
   native CCTV, FINAL or app-promotion result.

## Implementation admission and limits

This source-only design permits at most **one selected training update**, four
candidate trials, four explicit restores to original and one final selected
application: **nine parameter applications total**. Trial writes and restores
must be journaled just as actual applications; they are not hidden as inference.
No Adam/momentum object, new autograd query or unbounded line search is proposed.
All actual trial/application work remains under the user's manual L4 workflow.
Restore original heads after every trial, including the fourth, before the one
final selected application. A complete but quality-ineligible trial does not
cancel the registered remaining trials. Any execution, nonfinite, bound, frozen
tensor, RNG, copy or resource invariant failure immediately stops the test.
A partially applied write remains unknown; no restore may erase that outcome
or invent a completed application. There is no monitor-driven fallback.

The planned complete forward budget is **436**: initial56 quality cases, four
same-state repeats, initial64 optimization cases, four64-case trial banks and
one selected56-case final bank. If no candidate is eligible, the last56 and final
application are not attempted; the known stopped prefix is explicitly reported.
All four trials run in the registered order, so no candidate is silently omitted.
No monitor output may leak into candidate selection or scale choice.

Proposed timing: worker1200 seconds, external1260 plus20 cleanup; each phase180
seconds. Export300/330 seconds separately. Require8GiB free before launch and
retain4GiB; RAM10GiB, reserved CUDA18GiB, new outputs/archive2GiB each. Exact
runtime is unmeasured. These are **design requirements, not implemented limits**.

Before sealing, pure tests must cover FP32 candidate and restore accounting,
exact original-state independence, the fixed four-scale order, all16 eligibility
endpoints, quantization-code crossing fixtures, strict blur selection, no monitor
selection leakage, deterministic first-eligible choice and zero-candidate stop.
Independent review must establish actual trial/restore/commit counters, full
timers and failure capture before any runnable guide is published. Preserve all
historical immutable packets and their failed states.

This finite selection can still fail. The present evidence does not establish
that a different scalar will fix discrete PNG behavior or generalize. If the
registered trials fail, stop this recipe and review the objective/data or model
path rather than extending the scale list. U96 and original u64 remain retained.
Broader DEV and later independent evaluation remain mandatory. Native/wild stay
unpaired; reviewed preparation remains separate. Full goal **ACTIVE/incomplete**.
