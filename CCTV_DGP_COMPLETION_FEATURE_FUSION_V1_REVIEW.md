# Completion architecture diagnostic after the processing comparisons

The next diagnostic compares the frozen supporting CodeFormer inpainting
component with and without direct encoder-feature fusion. Our own trained DGP
remains the primary visible restorer. Its independently audited V39 gradient
proof and prepared manual V40 capacity pilot remain separate.

Input footprints, expanded conditioning and margin blending leave central
glare/anatomy defects and exterior joins. The invalid assumption is that those
processing changes alone would resolve the full covering scope. The architecture
question required by AGENTS.md was asked; the human answered “apply the best
approach”. This permits the following finite frozen diagnostic, not automatic
training or application adoption.

The pinned author implementation predicts latent codes from observed context
before decoder fusion. Three stages add encoder features when w is positive;
w=0 bypasses that addition. It does not remove the encoder's contribution to
predicted codes. Removing fusion can alter covering remnants, anatomy or texture
and can worsen fidelity. This is a hypothesis to measure, not an established
cause of our visible defects.
[Pinned author architecture](https://raw.githubusercontent.com/sczhou/CodeFormer/b33cc7d639d6545bfcccc7e0bc6ae51f24e79c2b/basicsr/archs/codeformer_arch.py).

The official inpainting script fixes w=1 and adain=False. Our w=0 setting is
an explicitly nondefault inference ablation using the same inpainting weights,
not a claim about the author's validated inpainting performance.
[Pinned author inpainting script](https://github.com/sczhou/CodeFormer/blob/b33cc7d639d6545bfcccc7e0bc6ae51f24e79c2b/inference_inpainting.py).
