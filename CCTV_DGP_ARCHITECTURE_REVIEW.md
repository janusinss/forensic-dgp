## What the current model implements

`models/dgp_synthesizer.py` constructs a MobileNetV2 feature pyramid, convolutional
heads and an RGB residual added to the observed image. The forward path contains
no pretrained face-generator decoder or optimized generative latent code.
Historical class naming and checkpoints remain intact. The inference adapter
does not use `generate_top_k` or its display sharpening.

Source pins: synthesizer
`459d2fcd1e489f6e6eb68326a20ac0c4b1e6811f9e0184630194eb99c05d7397`;
FPN `377f6a3ba1921c6906b6bc35a5308d12d5079042277a474a27c8db4f733d1cdc`.
These files live beneath the Windows root; corresponding VM package files are
`~/forensic-dgp/cctv_dgp_mixed_vm_v9_r2/models/` after verified extraction.

DeblurGAN-v2 introduced an FPN generator for motion deblurring and supports
MobileNet backbones. This supports the project's documented architecture
lineage; it does not establish a learned generative face prior in our current
forward path. [DeblurGAN-v2, ICCV 2019](https://arxiv.org/abs/1908.03826).

The published DGP method uses a GAN trained on large image collections and
progressively adapts its generator for image reconstruction. The present
feed-forward FPN restorer is a different implementation; naming alone does
not demonstrate equivalent methodology.
[Deep Generative Prior, ECCV 2020](https://arxiv.org/abs/2003.13659).

GFP-GAN incorporates a pretrained face GAN using spatial conditioning to
balance realistic detail with input fidelity. Its reported experiments motivate
investigating a face-specific prior, without proving it would improve our model
or preserve identity on our CCTV sources.
[Generative Facial Prior, CVPR 2021](https://arxiv.org/abs/2101.04061).

## Codebook prior and the differentiable contribution

The published CodeFormer uses a learned codebook and transformer to predict
face codes, with a controllable feature connection for quality/fidelity.
[CodeFormer, NeurIPS2022](https://arxiv.org/abs/2206.11253).
Its official training separates codebook learning, code-sequence prediction and
the controllable module. A pretrained codebook can be reused explicitly rather
than claimed newly learned by our project.
[Author training procedure](https://github.com/sczhou/CodeFormer/blob/master/docs/train.md).

Local source inspection shows two relevant boundaries: the restoration wrapper
uses `torch.inference_mode`, and the official network's normal decoding path
chooses hard top-1 code indices. Its `code_only=True` path returns logits and
encoder features. Therefore, training an RGB conditioner through the existing
inference wrapper would not establish the intended gradient path. A proposed
DGP feature conditioner needs a separately versioned differentiable interface
and latent/code supervision or an explicitly justified differentiable decoder.
Frozen pretrained parameters and our trainable parameters must be listed and
checked separately. No such training implementation or gradient proof is claimed.
