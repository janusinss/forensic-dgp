## Why this tradeoff is plausible, but not proven causal

The admitted architecture globally transforms encoder features into256 code predictions. Ordinary inference performs hardtop1 lookup and uses a fixed generator, with frozen R1 encoder features injected through fusion atw=1. The uniform CE objective supervises every token against clean-context labels; final output copies visible RGB exactly and exposes only generated removal support. Consequently, much of the learning objective targets positions whose generated pixels are not directly delivered. However, visible-position codes can still influence the hole through generator convolutions/attention and fusion. It would be incorrect to assume that visible-position CE is useless or to discard it based on grid geometry alone.

The exact app replaces removed pixels with white before encoding. Predictor-only learning cannot repair the encoded context/fusion features, and its hard code choices are not optimized directly for the final hole/boundary loss. The current evidence supports reviewing spatial supervision and frozen-path compatibility, rather than claiming that32 more updates or a larger LR must work. Tiny weight deltas, lower CE, and code agreement cannot independently predict delivered quality. An unseen person's precise hidden clean-context token is also an ambiguous target; the required deliverable remains a plausible estimate preserving visible appearance.

Gray color is a second limitation. Reusing all eight strict-gray cases from each of the previous four probe arms gives mean PNG support channel spread: A actual/R1fusion4.6712; B actual/no-fusion8.6040; C clean-context oracle/R1fusion6.2603; D clean-context oracle/no-fusion5.5036. All32 raw-to-PNG values were rechecked. Even the same-codebook clean oracle without fusion does not guarantee grayscale output. Code CE alone therefore cannot be assumed to enforce appearance/style. This does not prove the prior has no grayscale capacity, nor justify removing fusion: both no-fusion variants previously failed preservation. Preserve the gray gate; do not recolor saved raw outputs or quietly redefine a trained gain as display processing.
